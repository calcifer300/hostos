## 0. The headline finding

The working directory held **the older clone**. The production deployment
(`hostos-ten.vercel.app`, Vercel deployment `dpl_jo92aURjYicDzTX3HeLXZTymjdrK`, 10 Sep 2026) was built
from `C:\Users\AMD\Desktop\hostOS-unified\hostos`, branch **`unified`** at commit `bdefaaf`
"Per-fleet email alerts (migration 0016)" — **12 commits and 7,818 lines ahead** of
`hostos-v0.1/hostos` (`demo-polish` @ `5131605`). Those 12 commits already:

- merged Karl's five tools (timezones, bulk-paste parser, countdown engine, Turo policy library,
  AI-reply, content-scanner) into the app and into **one** Companion extension (v3.6.0);
- added `/board` (cross-fleet ops board), `/library` (725 Turo help-centre articles, ranked
  full-text search), per-fleet email alerts, grounded reply drafting (`/api/companion/draft`);
- added migrations 0014–0016 (applied to production — the live `/library` search works);
- added a dependency-free test runner (`npm test`, 65 assertions).

The GitHub remote (`calcifer300/hostos`) does **not** have these commits. Nothing in the working
directory referenced tables from 0014–0016 because the code that reads them was never copied here.

**Decision:** the unified branch is the base. The working directory becomes the single repository
root (app at root, exactly as deployed). Everything else is vendored or archived — never deleted
before its replacement is in place.

## 3. Database review (0001 → 0016)

Findings, each addressed in migration **0017** onward (additive, idempotent):

1. `knowledge_base` and `automation_settings` still carry a `user_email` primary key from 0002; the app
   writes `host_id` (0013). Repair: keep the columns, make `user_email` nullable so Companion-only
   fleets can insert, keep the `host_id` unique indexes as the real keys.
2. `trip_messages.host_id`, `trip_events.host_id` have no `ON DELETE CASCADE` (0003/0004 predate the
   pattern 0009+ use). Repair: re-point the FKs with cascade so deleting a fleet cannot orphan rows.
3. `trips.plate` is a soft reference by design (a trip may arrive before its vehicle) — keep, but add
   the missing composite index `(host_id, plate)` used by the vehicle page and the prune guard.
4. `synced_emails`/`gmail_accounts` are `user_email`-keyed — correct (Gmail is a personal connection); keep.
5. No `updated_at` triggers anywhere; every writer sets it by hand. Repair: one `set_updated_at()`
   trigger function applied to tables that carry the column.
6. RLS is enabled with zero policies on every table, service-role only — deliberate and kept;
   documented in ARCHITECTURE.md. `search_turo_articles` correctly uses `security invoker`.
7. Missing product tables: restaurants module, unified notifications, tasks, dashboard layouts.
   Added in 0017–0019.
8. `hosts.timezone` exists (0009) but the dashboard ignored it — a code fix, not schema.
